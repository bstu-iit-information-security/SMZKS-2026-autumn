## Лабораторная работа №3. Разработка модулей ядра операционной системы для динамического перехвата системных вызовов с использованием технологии eBPF

**Цель работы:** практическое освоение методов разработки программ расширенного фильтра пакетов Беркли (eBPF) на языке C для мониторинга событий уровня ядра, динамического перехвата системных вызовов (kprobes/tracepoints) и выявления аномального поведения процессов в операционной системе Linux с использованием фреймворка BCC (BPF Compiler Collection).

Инструкция по подготовке стенда на личных устройствах:
Так как программы eBPF компилируются «на лету» под конкретное ядро ОС, работа выполняется **исключительно в среде Linux**.
* **Для пользователей Windows:** необходимо использовать подсистему WSL2. Откройте PowerShell от имени администратора и выполните: `wsl --install -d Ubuntu-22.04`. После перезагрузки работайте внутри терминала Ubuntu.
* **Для пользователей macOS (Apple Silicon M1/M2/M3 или Intel):** необходимо установить полноценную виртуальную машину с Ubuntu 22.04 (рекомендуется использовать бесплатный гипервизор UTM или VirtualBox). 
* **Внимание!** Использование Docker Desktop на Windows и macOS для данной работы **запрещено**, так как встроенная легковесная ВМ Docker не содержит заголовочных файлов ядра, необходимых для компиляции eBPF-программ.

Настройка окружения внутри Ubuntu/WSL2:
1. Обновите пакеты базы данных: `sudo apt-get update`
2. Установите базовые утилиты BCC и Python-библиотеки: 
   `sudo apt-get install -y bpfcc-tools python3-bpfcc`
3. Установите заголовочные файлы ядра:
   * **Для полноценных виртуальных машин (VirtualBox/UTM):** 
     выполните `sudo apt-get install -y linux-headers-$(uname -r)`
   * **Для пользователей WSL2 (Windows):** шаг с установкой `linux-headers` пропускается, так как Microsoft использует кастомное монолитное ядро. Установленных пакетов из пункта 2 будет достаточно для работы базовых kprobes. Если BCC всё же потребует исходники ядра при запуске скрипта, вам придется перейти на использование полноценной виртуальной машины (VirtualBox).
4. Все скрипты, взаимодействующие с подсистемой eBPF, должны запускаться строго с привилегиями суперпользователя (`sudo python3 script.py`).

**Теоретическая база**

eBPF (Extended Berkeley Packet Filter) — это технология, позволяющая выполнять изолированные программы (байт-код) внутри ядра Linux без необходимости изменения исходного кода ядра или загрузки дополнительных модулей (LKM). Программы eBPF работают в безопасной виртуальной машине, проходят строгую верификацию перед запуском (на отсутствие бесконечных циклов и несанкционированного доступа к памяти) и обеспечивают минимальные накладные расходы на производительность.

Архитектурно разработка под eBPF делится на два контекста:
1. **Kernel Space (Пространство ядра):** Программа пишется на ограниченном подмножестве языка C. В ядре зонд "прикрепляется" к определенным хукам — `kprobes` (динамический перехват входа в любую функцию ядра), `kretprobes` (перехват возврата из функции) или `tracepoints` (статические точки трассировки, например `tracepoint:syscalls:sys_enter_openat`). В этой части осуществляется сбор телеметрии, первичная фильтрация и упаковка данных.
2. **User Space (Пространство пользователя):** Скрипт (чаще всего на Python, Go или C/C++) загружает скомпилированный C-код в ядро, читает переданные данные через специальные BPF-карты (BPF Maps) или кольцевые буферы (Perf Ring Buffers) и выводит алерты администратору. Для упрощения этой интеграции используется фреймворк BCC (BPF Compiler Collection).

Производительность систем мониторинга:
Золотое правило eBPF заключается в том, что фильтрация событий должна происходить на стороне ядра. Системные вызовы происходят тысячи раз в секунду. Если eBPF-программа отправляет данные о *каждом* вызове в пространство пользователя для анализа (в Python), это приведет к переполнению буфера и колоссальной нагрузке на процессор. Программа на C должна самостоятельно проверять условия (например, сравнивать строку с путем к файлу `/etc/shadow`) и использовать функцию `bpf_perf_event_output()` только для реальных аномалий.
