## Лабораторная работа №2. Защита веб-периметра и ограничение интенсивности сетевого трафика средствами межсетевых экранов прикладного уровня

**Цель работы:** практическое освоение методов развертывания межсетевых экранов прикладного уровня (WAF), написания пользовательских правил фильтрации L7-угроз, а также проектирование механизмов защиты от DDoS-атак и ограничения частоты запросов (Rate Limiting) на базе обратного прокси-сервера Nginx.

Инструкция по подготовке и запуску стенда:
1. Установите Docker и Docker Compose (рекомендуемая среда для развертывания Nginx + WAF).
2. Для задания 3 вам потребуется утилита Apache Bench (`ab`). На Linux/WSL она устанавливается командой `sudo apt install apache2-utils`. На Windows можно использовать аналоги — утилиты `hey` или `bombardier`.
3. Перейдите в директорию стенда (где находится файл `docker-compose.yml`) и выполните команду: `docker-compose up -d`. 
4. Убедитесь, что уязвимое веб-приложение доступно напрямую по порту 5000 (`http://127.0.0.1:5000`), а защищенный контур через Nginx WAF доступен по порту 80 (`http://127.0.0.1`).
5. Для выполнения всех шагов с вашего рабочего компьютера (терминала) используются консольные утилиты `curl` и `ab`.

**Теоретическая база**

Межсетевой экран прикладного уровня (Web Application Firewall, WAF) — это специализированное средство защиты, которое анализирует трафик на прикладном (седьмом) уровне модели OSI. В отличие от классических сетевых экранов, фильтрующих трафик по IP-адресам и портам (L3/L4), WAF «понимает» структуру протокола HTTP/HTTPS, разбирает заголовки, куки, параметры GET/POST и тело запроса. Это позволяет выявлять атаки, такие как SQL-инъекции, межсайтовый скриптинг (XSS) и удаленное выполнение кода (RCE). В данной работе используется ModSecurity с базовым набором правил OWASP Core Rule Set (CRS).

Пользовательские правила WAF пишутся на специализированном языке (синтаксис SecRule). Они позволяют блокировать специфичные угрозы нулевого дня (0-day) или логические атаки, не покрываемые стандартными сигнатурами (например, блокировка конкретных вредоносных User-Agent). Каждому правилу должен быть присвоен уникальный идентификатор (id).

Ограничение интенсивности трафика (Rate Limiting) — ключевой механизм защиты от DDoS-атак прикладного уровня (L7) и брутфорса. На уровне обратного прокси (Nginx) используется алгоритм "Leaky Bucket" (дырявое ведро). 
Основные параметры настройки:
* `rate` — скорость обработки запросов (например, `10r/s` — 10 запросов в секунду).
* `burst` — размер очереди (буфера) для всплесков трафика. Запросы сверх `rate`, но в пределах `burst`, задерживаются, чтобы соответствовать заданной скорости. Все запросы сверх `burst` немедленно отбрасываются с ошибкой 503.

Атака Slowloris (Slow HTTP Denial of Service) — тип DDoS-атаки, при которой злоумышленник устанавливает множество соединений с сервером и отправляет HTTP-заголовки крайне медленно, не завершая запрос. Это исчерпывает пул доступных подключений сервера (worker connections). Защита на уровне прокси-сервера обеспечивается жестким ограничением времени ожидания передачи заголовков и тела запроса от клиента.
